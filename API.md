# MFS Organisations API and webhooks

> Online version with screenshots: https://managedfreescout.com/support/mfsorganisations-api/
> Generated from the manual's source document; do not edit this file by hand.

## Getting started

The MFS Organisations API lets other systems read and maintain your organisations, and its webhooks tell them when something changes. It is part of MFS Organisations and builds on FreeScout's official **API & Webhooks** module: without that module there is no API.

- **Base URL:** `https://<your FreeScout>/api/organisations`
- **Authentication:** the same API keys as FreeScout's own API, in the header `X-FreeScout-API-Key: <key>` (or `?api_key=<key>`). Keys are managed under **Manage → Settings → API & Webhooks**.
- **Format:** JSON in and out, field names in camelCase. Lists come as `_embedded` plus a `page` block (`size`, `totalElements`, `totalPages`, `number`), like FreeScout's own API. Use `page` and `pageSize` (max. 200) to page through. Dates are UTC, e.g. `2026-11-06T16:34:46Z`.
- **Created:** answers `201 Created` with the new id in the `Resource-ID` header.

**What a key may do** follows its owner, like in the screens:

| API key | Sees | May change | May delete |
| --- | --- | --- | --- |
| Personal key of an agent | Organisations of the agent's mailboxes | Only with the permission "Users are allowed to manage organisations" | No |
| Personal key of an administrator | Everything | Yes | Yes |
| The module's main API key | Everything | Yes | Yes |

**Errors** use FreeScout's error body, with the field in `path`:

```json
{
  "message": "acme.com already belongs to Acme Ltd",
  "_embedded": { "errors": [ { "path": "domain", "message": "acme.com already belongs to Acme Ltd", "source": "JSON" } ] }
}
```

| Status | Means |
| --- | --- |
| 400 | A field is missing or not valid |
| 401 | No or wrong API key |
| 402 | MFS Organisations has no active licence |
| 403 | The key may not do this |
| 404 | Not found, or not visible to this key |
| 409 | Conflict: name or domain already taken, or the organisation is not empty |

## Endpoints

All paths are under `/api`. "Manage" means the key needs the permission to manage organisations; "Admin" means an administrator's or the main key.

| Method and path | Does | Needs |
| --- | --- | --- |
| `GET /organisations` | List organisations. Filters: `search` (name), `domain`, `type`, `active` (true/false) | Read |
| `POST /organisations` | Create an organisation, optionally with `domains` and `mailboxIds` | Manage |
| `GET /organisations/{id}` | One organisation, all fields. `?embed=departments` adds its departments | Read |
| `PUT` or `PATCH /organisations/{id}` | Change it: only the fields you send change. `domains` replaces the whole list | Manage |
| `DELETE /organisations/{id}` | Delete an empty organisation (409 otherwise: send `active: false` instead) | Admin |
| `POST /organisations/{id}/domains` | Add one domain: `{"domain": "acme.com"}`. Links its existing addresses at once | Manage |
| `DELETE /organisations/{id}/domains/{domain}` | Remove a domain; addresses already linked stay linked | Manage |
| `GET /organisations/{id}/addresses` | The linked addresses | Read |
| `POST /organisations/{id}/addresses` | Link an address by hand: `{"email": "…", "movePastConversations": false}` | Manage |
| `DELETE /organisations/{id}/addresses/{email}` | Remove it: past conversations are unlinked (except ones set by hand) and it is never linked automatically again | Manage |
| `GET /organisations/{id}/conversations` | Its conversations, newest first. Filters: `status` (open, active, pending, closed), `mailboxId` | Read |
| `GET /organisations/{id}/departments` | Its departments, with their path ("Finance › Payroll") | Read |
| `POST /organisations/{id}/departments` | Add a department: `{"name": "…", "parentId": null}` | Manage |
| `GET /organisations/lookup` | Which organisation `?email=` or `?domain=` belongs to (see Examples) | Read |
| `GET /conversations?organisationId={id}` | FreeScout's own conversation list, limited to one organisation | Read |

Creating, changing and linking a domain answer with the organisation plus a `_report`: how many existing addresses were linked, how many conversations were added, and which domains were refused and why.

**Locations** (since version 1.1): an organisation's sites, buildings, floors and rooms, as a tree.

| Method and path | What it does | Access |
| --- | --- | --- |
| `GET /api/organisations/{id}/locations` | All locations of the organisation, in tree order, each with its `path` | Read |
| `POST /api/organisations/{id}/locations` | Add a location: `{"name": "Building A", "type": "building", "parentId": 1, "address": null, "notes": null}` | Manage |
| `PUT` / `PATCH /api/organisations/{id}/locations/{locationId}` | Change a location; only the fields sent change. `parentId: null` moves it to the top level; a parent inside its own sub-tree is refused | Manage |
| `DELETE /api/organisations/{id}/locations/{locationId}` | Delete it: sub-locations move up one level, addresses keep their organisation and lose this location | Manage |

`type` is one of `site` (default), `building`, `floor`, `room`, `other`. A location answers with `id`, `organisationId`, `name`, `type`, `parentId`, `path` ("Head office › Building A"), `address`, `notes`, `createdAt` and `updatedAt`. `GET /api/organisations/{id}?embed=locations` (or `embed=departments,locations`) includes them in the organisation. Addresses carry a read-only `locationId`; agents set it in FreeScout.

## The organisation object

The same fields are used to read, create and change, and in the webhooks. In a list only the first group is returned; a single organisation has all fields.

| Field | Type | Notes |
| --- | --- | --- |
| `id` | integer | Read only |
| `name` | string | Required when creating; unique; max. 191 characters |
| `type` | string | `company`, `non_profit`, `association`, `government`, `education` or `other` (default `company`) |
| `active` | boolean | Default true. Inactive = keeps its history, links nothing new |
| `autoLink` | boolean | Default true. Link addresses of its domains automatically |
| `color` | string | Badge colour, e.g. `#3f8abf` |
| `alert` | string or null | Shown on every conversation; max. 255 characters |
| `domains` | array of strings | Free-mail, own and other organisations' domains are refused |
| `createdAt`, `updatedAt` | string | UTC, read only |
| `cocNumber`, `vatNumber` | string or null | Single organisation only |
| `country` | string or null | Two letters, e.g. `NL` |
| `address`, `phone`, `website`, `notes` | string or null | `notes` is internal |
| `mailboxIds` | array of integers | Mailboxes it belongs to; empty = every mailbox |

```json
{
  "id": 12,
  "name": "Acme Ltd",
  "type": "company",
  "active": true,
  "autoLink": true,
  "color": "#3f8abf",
  "alert": "Contract ends 31 Dec",
  "domains": ["acme.com", "acme.co.uk"],
  "createdAt": "2026-11-06T16:34:46Z",
  "updatedAt": "2026-11-06T16:40:02Z",
  "cocNumber": "12345678",
  "vatNumber": null,
  "country": "GB",
  "address": null,
  "phone": "+44 20 7946 0000",
  "website": "https://acme.com",
  "notes": null,
  "mailboxIds": []
}
```

**An address** (from the addresses endpoints and the address webhooks): `email`, `organisationId`, `departmentId`, `source` (`domain`, `manual` or `excluded`), `active`, `activeFrom`, `activeTo` (dates), `inForce` (true when it counts today) and `createdAt`.

## Examples

**Create an organisation with its domains.** Existing addresses on those domains are linked straight away; the `_report` says what happened.

```bash
curl -X POST https://support.example.com/api/organisations \
  -H "X-FreeScout-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"name": "Acme Ltd", "type": "company", "domains": ["acme.com", "gmail.com"], "alert": "Key account"}'
```

```json
{
  "id": 12, "name": "Acme Ltd", "domains": ["acme.com"], "...": "...",
  "_report": {
    "addressesLinked": 9,
    "conversationsAdded": 8,
    "domainsRefused": ["gmail.com is a free-mail domain: link its addresses by hand"]
  }
}
```

**Look up an address.** Answers which organisation the address belongs to and how: `address` (linked by hand) or `domain`.

```bash
curl "https://support.example.com/api/organisations/lookup?email=jan@acme.com" -H "X-FreeScout-API-Key: $KEY"
```

```json
{ "organisation": { "id": 12, "name": "Acme Ltd", "...": "..." }, "matchedBy": "domain" }
```

No organisation answers `404` with `"organisation": null`. For a free-mail or own domain `blocked` says so (`"freemail"` or `"own"`); for an address that was removed by hand `matchedBy` is `"excluded"`.

**Link a private address by hand.**

```bash
curl -X POST https://support.example.com/api/organisations/12/addresses \
  -H "X-FreeScout-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"email": "secretary.acme@gmail.com"}'
```

**Keeping a CRM in step.** A simple, robust sync:

1. Keep the FreeScout organisation id in a field of the company in your CRM.
2. Company created in the CRM: `POST /organisations` with its name and domains, and store the returned id.
3. Company changed: `PATCH /organisations/{id}` with the changed fields. Send `domains` only when the domain list changed; it replaces the list.
4. Company ended or deleted: `PATCH` with `"active": false`. Its history stays in FreeScout.
5. The other way round: subscribe to the organisation webhooks to update the CRM when agents change things in FreeScout.

## Webhooks

The organisation events appear in the event list of a webhook under **Manage → Settings → API & Webhooks**. FreeScout sends them the same way as its own webhooks: a POST with a JSON body, the event in the `X-FreeScout-Event` header and a signature in `X-FreeScout-Signature`, in the background, with its retry and log.

| Event | Sent when | Body |
| --- | --- | --- |
| `organisation.created` | An organisation is created (screen, import or API) | The organisation, all fields, domains included |
| `organisation.updated` | Its fields, domains or mailboxes change | The organisation, all fields |
| `organisation.deleted` | It is deleted (or merged into another one) | `id` and `name` |
| `organisation.address_linked` | An address is linked, by domain or by hand | The address, plus `organisation` (`id`, `name`, `type`) |
| `organisation.address_removed` | An address is removed or moves to another organisation | The address, plus the organisation it left |

A few things to know:

- One change in the screens or one API call sends one `created` or `updated`, sent after the request is complete, so it always holds the final state.
- Adding a domain sends an `address_linked` for each existing address it links. The backfill sends no webhooks.
- Setting an address back to "Automatic" on the customer form sends `address_removed` followed by `address_linked`.

**Location events** (since version 1.1): `organisation.location_created`, `organisation.location_updated` (also a move in the tree) and `organisation.location_deleted`. The first two send the location object; the delete sends `id`, `name`, `type` and `parentId`. All three add `organisation` with the organisation's `id` and `name`.

**Organisation on conversation webhooks.** FreeScout's own conversation webhooks (`convo.created`, `convo.status` and the others) get one extra field, so a receiver can route by organisation without calling the API:

```json
{
  "id": 52,
  "number": 52,
  "subject": "Invoice question",
  "...": "...",
  "organisation": { "id": 12, "name": "Acme Ltd", "type": "company" }
}
```

`organisation` is `null` when the conversation has none.
