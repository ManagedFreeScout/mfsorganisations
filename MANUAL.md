# MFS Organisations manual

> Online version with screenshots: https://managedfreescout.com/support/mfsorganisations/
> Generated from the manual's source document; do not edit this file by hand.

## Overview

MFS Organisations groups your FreeScout customers into organisations, so every conversation shows which company, club or institution it comes from. You link e-mail addresses to an organisation by its domain (everyone at acme.com) or by hand (a secretary's gmail address), and from then on every new conversation from those addresses is placed under that organisation automatically.

What you get:

- **An organisation page** with its details, domains, addresses, departments and all its conversations.
- **A coloured badge** in the conversation list and on Kanban cards. Click it to see all conversations of that organisation.
- **An organisation block** next to every conversation, with an optional alert such as "Contract ends 31 Dec".
- **Search, Kanban and Workflows** that understand organisations: filter, sort and route by organisation.
- **A REST API and webhooks** to keep organisations in step with your CRM or billing system.

In FreeScout every e-mail address is its own customer. MFS Organisations therefore links per address: one person who writes from both a work address and a private address can belong to an organisation with one address and to none with the other.

**Requirements:** FreeScout 1.8 or later. Kanban, Workflows and API & Webhooks are optional official modules; MFS Organisations adds to them when they are installed. One licence covers one FreeScout installation.

## Installation and licence

Install the module like any other FreeScout module, then activate your licence key.

1. **Download** the latest mfsorganisations.zip from the Downloads block on this page, or from your customer account.
2. **Unpack** it into your FreeScout's `Modules` folder, so you get `Modules/MFSOrganisations`.
3. **Activate** it in FreeScout under **Manage → Modules**: click **Activate** on the MFS Organisations card. FreeScout creates the module's own tables; it changes none of FreeScout's tables.
4. **Enter your licence key** under **Manage → Settings → MFS Organisations**, in the Licence panel, and click **Activate licence**. The key is in the confirmation e-mail you received after your purchase.

The licence is checked with the licence server every 6 hours. Without an active licence the module switches off: badges, the menu item and the organisation block disappear. Your organisations, domains and links stay stored and are back as soon as the licence is active again.

**Updates** appear under Manage → Modules with an **Update** button; no download is needed.

**Who can do what:**

| Who | Can |
| --- | --- |
| Every agent | See organisations of the mailboxes they have access to, badges, the organisation block, search and filter |
| Agents with the permission "Users are allowed to manage organisations" | Create and change organisations, domains, addresses and departments; import; change a conversation's organisation |
| Administrators | All of the above, plus settings, backfill, merging and deleting organisations |

You give the permission per user under **Manage → Users → (user) → Permissions**.

## Creating organisations

Organisations are never created automatically: you decide which ones exist. There are four ways to add them.

- **By hand:** **Manage → Organisations → New organisation**.
- **From a conversation:** when a conversation has no organisation and comes from a business domain that no organisation has yet, its organisation block shows **Create organisation for acme.com**. It opens the new-organisation form with the domain filled in.
- **CSV import:** **Manage → Organisations → Import CSV** (see below).
- **Through the API**, for example from your CRM (see API and webhooks).

![Manage menu with the Organisations item](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/01-menu.png?v=edf5fa05)

![The organisations list with counts, search and filters](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/02-list.png?v=07ddb1c5)

**The fields of an organisation:**

| Field | What it does |
| --- | --- |
| Name | Must be unique |
| Type | Company, non-profit, association, government, education or other. Usable in Workflows |
| Status | Active, or inactive: an inactive organisation keeps its history, but new addresses and conversations are no longer linked to it |
| Alert | Optional short warning shown on every conversation of the organisation, e.g. "Contract ends 31 Dec" or "Phone support only" (max. 255 characters) |
| Colour | The colour of its badge |
| Domains | One per line; see Domains and automatic linking |
| Mailboxes | Agents see the organisation when they have access to at least one of these mailboxes. All ticked = every mailbox, also ones you add later |
| Registration, Contact, Address | Chamber of Commerce no., VAT no., country, phone, website, postal address |
| Notes | Internal notes; only agents see them |

![An organisation's Details tab](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/03-details.png?v=93b13004)

**CSV import.** The first line holds the column names; only `name` is required. Other columns: `type`, `domains`, `coc_number`, `vat_number`, `country` (two letters), `phone`, `website`. Commas and semicolons both work as separator. Put several domains in one cell, separated by spaces. A row whose name already exists updates that organisation instead of adding a second one. Domains that can't be added (free-mail, your own, or another organisation's) are listed after the import.

```csv
name;type;domains;country;website
Acme Ltd;company;acme.com acme.co.uk;GB;https://acme.com
Tennis Club Enjoy;association;;NL;
```

## Domains and automatic linking

An organisation's domains decide which addresses belong to it: add acme.com, and every address ending in @acme.com is linked to Acme, both the existing ones and every new one.

- **Right away:** when you add a domain, the existing addresses with that domain are linked at once, and their conversations get the organisation. The message after saving says how many.
- **From then on:** a new address with that domain is linked when its first conversation arrives, and that conversation gets the organisation immediately.
- **Exact domains only:** acme.com doesn't cover mail.acme.com; add that as a second domain.
- **One owner:** a domain belongs to one organisation only. Adding a domain that another organisation already has is refused, with that organisation's name.
- **Linked by hand wins:** an address you linked or removed by hand is never changed by a domain.
- **Switched off:** an inactive organisation, or one with "Link addresses with these domains automatically" unticked, links nothing new by domain. Ticking it again links its domains' addresses at once.
- **Removing a domain** stops new links. Addresses already linked through it stay linked; remove them on the Addresses tab if they no longer belong.

**Free-mail and your own domains are never linked by domain.** One gmail.com address says nothing about where someone works, and your own mailbox domains would link every colleague. These domains are refused as organisation domains:

- **Free-mail domains:** gmail.com, outlook.com, hotmail.com, icloud.com, ziggo.nl, kpnmail.nl and about 50 more. Administrators can change the list under **Manage → Settings → MFS Organisations → Free-mail domains**.
- **Your own domains:** the domains of your mailboxes' addresses and aliases. This list is automatic.

An address on such a domain can still be linked by hand: see Addresses.

## Addresses and departments

The **Addresses** tab of an organisation lists every linked address, with its customer, how it was linked (Domain or By hand) and since when. Here you link addresses by hand, change their department and period, or remove them.

![The Addresses tab: department, Active and the link period per address](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/04-addresses.png?v=473e7611)

**Link an address by hand.** Type one or more addresses at the top of the Addresses tab (separated by spaces) and click **Link**. Use this for addresses a domain can't catch, such as the club secretary's gmail address. The address's conversations that have no organisation yet get this one. Tick **also move its past conversations here** to move conversations that are already under another organisation too.

You can do the same from the customer: open the customer's profile, **Edit**, and pick the organisation per e-mail address:

- **Automatic:** the domain decides (the option shows which organisation that is).
- **None: unlink past conversations, never link automatically.**
- **Link by hand to** an organisation of your choice.

![The organisation field on the customer edit form](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/11-customer-form.png?v=ed3d7dfa)

**Remove or end a link?** Two different things:

| You want to say | Use | Past conversations | New conversations |
| --- | --- | --- | --- |
| This address doesn't belong to this organisation | **Remove** | Unlinked, except ones an agent changed by hand | Never linked automatically again |
| This person worked here, but left (or starts later) | **Linked from / until** dates, or untick **Active** | Stay under the organisation | Not linked outside the period |

The confirmation for Remove says how many conversations it unlinks. Removed addresses appear under **Excluded** at the bottom of the tab; **Link again** undoes the removal. Rows that are not in force today are shown greyed out.

**Departments** are optional: use them when an organisation has teams or locations you want to tell apart. On the **Departments** tab you add a department at the top level or under another one, rename or move it, and delete it. Deleting keeps the addresses in the organisation; sub-departments move up one level. Give an address its department on the Addresses tab; its new conversations get that department, which shows in the organisation block.

![The Departments tab](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/05-departments.png?v=9a1e6045)

**Locations** (since version 1.1) are the organisation's places: sites, buildings, floors and rooms, in a tree. On the **Locations** tab you add a location with its type and its place in the tree ("Under Head office › Building A"), and under **Address and notes** a postal address and notes such as access codes or opening hours. Moving a location under one of its own children is refused. Deleting a location moves its sub-locations up one level and clears it from the addresses that used it.

Give an address its location on the **Addresses** tab or on the customer's edit form. The organisation block next to a conversation then shows where that person works, for example *Location: Head office › Building A › Room 2.14*. MFS Assets uses the same locations to record where each asset is.

![The Locations tab: sites, buildings, floors and rooms](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/14-locations.png?v=06a52ccc)

## Working with organisations

Once addresses are linked, the organisation shows up wherever agents work.

**The badge in the conversation list.** A coloured badge with the organisation's name stands before the subject. Click it to open all conversations of that organisation in FreeScout's search; Ctrl-click (Cmd on a Mac) opens them in a new tab. A click elsewhere on the row opens the conversation as usual.

![Organisation badges in the conversation list](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/07-list-badges.png?v=26e3897c)

**The organisation block on a conversation.** Under the customer, the block shows:

- the organisation's badge (click: all its conversations) and its **alert**, if it has one;
- the department, and "Set by hand" when an agent chose the organisation;
- a link to the **Organisation page** and to its other open conversations;
- **Change**: give this one conversation another organisation, or none. Only this conversation changes; to change it for all conversations of an address, use the Addresses tab.

![The organisation block with alert and department](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/08-conversation-block.png?v=f766b0a5)

![Change: another organisation for this one conversation](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/09-change.png?v=8a4e5e31)

A conversation keeps the organisation it got when it arrived. If someone later moves to another organisation, their earlier conversations stay where they were.

**Search.** FreeScout's search has a filter **organisation:**. Pick an organisation (type to search the list) to see its conversations, and its customers on the Customers tab.

![FreeScout's search filtered on one organisation](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/10-search.png?v=d70446b4)

**The organisation page.** Its **Conversations** tab lists all conversations of the organisation in the mailboxes you can see, filtered by mailbox and status, with **Export CSV**.

**Kanban** (with the official Kanban module). Cards show the organisation's badge after the subject. Next to Kanban's **Filters** button there is an organisation list: pick one to see only its cards. The column counts then count that organisation's cards. Your choice is remembered for all your boards until you pick **All organisations** again; it doesn't affect other agents.

**Workflows** (with the official Workflows module). Two extra conditions:

| Condition | Operators |
| --- | --- |
| Organisation | Is equal to, Is not equal to, Is set, Is not set |
| Organisation type | Is equal to, Is not equal to |

They work in workflows that run when a conversation is created (by a customer or an agent), forwarded or moved. Routing itself stays in Workflows, for example: *Organisation is equal to Acme* → assign to Sam and add the tag "key account".

**Customer profile.** A customer's page shows the badge of the organisation(s) their addresses belong to.

## Settings and maintenance

Administrators find the settings under **Manage → Settings → MFS Organisations**.

**Free-mail domains.** One domain per line. Addresses at these domains are never linked by domain, and the domains can't be added to an organisation. Your own mailbox domains are always left out, without being on this list.

**Display per mailbox.** Per mailbox, hide the badge in the conversation list, the organisation block on conversations, or both. Useful for an internal mailbox where everyone is from the same organisation.

**Link existing addresses (backfill).** Adding a domain links that domain's addresses at once. The backfill does the same for all your organisations together: run it after an import, or once after installing on a FreeScout with years of conversations. It never creates organisations.

1. Click **Preview**. Nothing changes yet. You see:
   - how many addresses FreeScout has, how many are **Already linked** and how many **Will be linked now**, per organisation;
   - how many are skipped: free-mail, your own domains, excluded by hand, or no organisation has the domain;
   - the **Most common domains without an organisation**, each with a **create organisation** link: the quickest way to see which organisations you still miss;
   - the conversations without an organisation.
2. Click **Link now**. The backfill runs in batches in the background with a progress bar; you can leave the page. It also runs on when nobody has the page open.

![The backfill preview](https://managedfreescout.com/wp-content/uploads/manuals/mfsorganisations/13-backfill-preview.png?v=78daa19a)

**Merge.** Created the same organisation twice? On the duplicate's **Details** tab, choose **Merge into…** and the organisation to keep. Its addresses, conversations, domains and departments move over, and the duplicate is deleted. Administrators only.

**Delete.** Only an organisation without addresses and conversations can be deleted (**Delete organisation** on the Details tab, administrators only). For any other organisation, untick **Active** instead: it keeps its history and links nothing new.

## API and webhooks

With FreeScout's official **API & Webhooks** module installed, MFS Organisations adds a REST API and webhooks, so a CRM, billing system or sign-up form can keep organisations up to date and react to changes.

- **REST API** under `/api/organisations`, with the same API keys as FreeScout's own API: list, create, change and deactivate organisations; add and remove domains; link and remove addresses; look up which organisation an address or domain belongs to; list an organisation's conversations and departments.
- **Webhooks**, selectable in the API & Webhooks webhook settings: organisation created, updated, deleted, address linked, address removed. FreeScout's existing conversation webhooks get an extra `organisation` field.

The API applies the same rules as the screens: free-mail and own domains are refused, and an API key only sees the organisations of its owner's mailboxes. Endpoints, fields and examples are on the separate page [MFS Organisations API and webhooks](https://managedfreescout.com/support/mfsorganisations-api/).
